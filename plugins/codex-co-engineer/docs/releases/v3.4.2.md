# Codex-Co-Engineer 3.4.2

3.4.2 reduces the setup work agents need for routine delegation and fixes
launch admission and cleanup issues on top of the 3.4.1 bounded-run runtime.

## What changed

- Instruct providers to honor the requested answer format and omit routine
  narration and unrequested evidence headings. Controller evidence requirements
  remain intact and do not act as an answer template.
  Successful Grok tasks return the answer after a fully settled tool round,
  following Grok's native response framing. Progress remains in task events.
  Ambiguous framing, inline web search, missing final text, overflow, and failed
  turns retain the existing aggregate output. Sanitization and size limits remain
  unchanged; other providers keep their existing output behavior.
- Native approval can be remembered for a repository and the selected providers.
  Accepting the form is sufficient; there is no second approval checkbox.
  Users can choose one-run access or revoke remembered access locally.
  Provider expansion, changed origin, and repository replacement ask again.
- Missing installed worker files fail before workspace preparation or provider
  dispatch, with clear reinstall and restart guidance.
- Provider instructions identify the assigned current working directory and
  controller-owned receipts, avoiding unnecessary source and skill searches.
- Slow provider acknowledgement stays active without replaying the prompt or
  blocking independent assignments. Later authoritative evidence updates the
  same run; terminal uncertainty and failed starts remain visible.
- Semantic runs return compact coordination results by default. Detailed run
  evidence is available through `task` with `run_id` and `view: "diagnostics"`.
  Structured responses use bounded fallback text; text-only clients can request
  `response_mode: "legacy"` for full-text encoding of the compact receipt.
  Detailed evidence still uses `view: "diagnostics"`. Existing single-task
  calls retain their behavior.
- Shorter launch instructions remove the fixed narration sequence and repeated
  setup guidance. Semantic duration estimates are optional, defaulting to ten
  minutes plus the existing 20% deadline margin.
- Launch prompts focus on the requested output, tests and brief review evidence.
  Co-Engineer's controller creates managed worktrees, while its worker wrapper
  owns verification, hidden writer tokens, lifecycle and machine receipts.
- Cursor SDK discovery uses a stable working directory, reports typed local
  discovery failures, and reuses successful discovery within the server process.
  This tolerates a deleted inherited working directory; it does not explain or
  prevent host replacement of the plugin cache.

- Cursor Cloud completion accepts the documented SDK result shape while
  preserving strict internal identity and evidence validation.
- Cursor Cloud result sanitization preserves legitimate answer text that
  overlaps its prompt instructions while still redacting full prompt echoes,
  credentials, and diagnostic prompt fragments.
- DSH uses the supported ACPX one-shot command, returning useful bounded
  errors instead of losing them inside a nested flow.
- Muse defaults to `meta/muse-spark-1.3-contributor` with XHigh reasoning
  through OpenRouter. The route uses `OPENROUTER_API_KEY` and does not receive
  the Meta credential.

- Native MCP form consent connects the stdio launch to a real host decision.
  Unsupported hosts fail closed with a capability blocker; interrupted
  decisions can be requested again on the existing run.
- Pending and terminal runs retain authoritative receipts and cursors through
  inspection and waits. Presentation separates planned assignments from
  completed evidence and only points to worktrees that exist.

- Semantic `run_request` launches satisfy the advertised MCP schema without
  redundant legacy fields. Assignment access follows its role when omitted;
  explicit conflicts and ambiguous dual envelopes are rejected.
- Skills reuse existing provider choices, submit one bounded run, and retain
  its identity through waits, attention, and continuation. Setup instructions
  stay outside the normal launch path.
- Disjoint writer directories no longer fail a duplicate overlap check.
  Cloud-only runs do not require a local process boundary; local and mixed
  runs retain that prerequisite.
- Repeated reconciliation avoids repeating cleanup grace periods while
  preserving the first grace period and ownership inspection.
- Linux ACP cleanup discovers detached descendants from process records so
  a failed external process-list command cannot silently hide running children.
- Preserve structured Cursor permission options through grouped questions,
  durable legacy attention batches, and same-session replies. Ordinary tool
  commands do not become questions from shell punctuation; genuine questions
  retain their full prompt text.
- Grok readiness distinguishes explicit login status from ancillary command
  errors.
- Future-dated repository-exposure approvals are rejected. Consent and wait
  tests no longer depend on expired dates, ambient network access, or sleeps.
- Optional model guidance covers Luna, Terra, Sol, and Astra with one task
  owner and bounded workers. Extra coordinators are optional; role and effort
  thresholds are heuristics. Model choices and settings remain host-owned.
- The package includes validated setup, troubleshooting, API, and release
  documentation so installed README links resolve within the package.

## Compatibility

The five public MCP tools, legacy single-task calls, full `run` envelopes,
and existing durable receipts remain supported. Persistence directory and
cache names retain their 3.4.1 identity. Existing Muse installations using
Meta directly must update their DSH profile to the OpenRouter endpoint/model
and configure an OpenRouter credential. Setup checks report incompatible
profiles rather than silently replacing an operator's configuration.

## Qualification

The exact-tree local release gate is the authority for provider-free checks.
The host must support MCP form elicitation. Desktop rendering, history bounds,
and live provider acceptance remain separate checks; see the historical
[3.4.1 qualification notes](v3.4.1.md). A local commit or passing synthetic test
suite does not establish those results. Publication requires the reviewed
candidate and its qualification evidence.
